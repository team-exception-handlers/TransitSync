# AI Usage

This file records how AI tools were used to build TransitSync. It is kept consistent with the two other places AI use is declared:

- **Source files:** applicable source and configuration files include an AI contribution: <level> declaration near the beginning, using the file formatâ€™s comment syntax. JSON attribution is recorded in AI_USAGE.md and the relevant pull request. Generated files are exempt.
- **Pull requests:** every feature or fix pull request declares the level for the code it introduces or substantially modifies, and lists the files that received substantial AI help (see `.github/pull_request_template.md`)

All three are good-faith estimates. When they disagree, the pull request is corrected before merge and this file is updated in the same pull request.

## Declaration levels

| Level | Meaning |
|---|---|
| No substantial AI-generated code | Written by a team member. AI was used at most for questions, explanations or small suggestions that were rewritten |
| Below 50% AI-generated | AI generated part of the code, but most of it was written by a team member |
| 50% or more AI-generated | AI generated most of the code. A team member reviewed, tested and edited it |

Code generated by AI counts as AI-generated even after a team member edits it. A declared level is never lowered later.

Crowding penalty (#23), 2026-11-05: Codex (OpenAI), 50% or more AI-generated.
Pull request: [#179](https://github.com/team-exception-handlers/TransitSync/pull/179).
Files: `simulator/trains/dwell.py`, `tests/simulator/trains/test_dwell.py`,
`README.md`, `AI_USAGE.md`. Added configurable quartic load scaling of passenger
service time, preserving base dwell with zero movements and existing callers
with crowding disabled. Hand-calculated examples, equal load increments near
capacity, full/empty loads, invalid inputs, NumPy counts and overflow tests
verify the standalone calculation. Review found NumPy integer arithmetic could
wrap to negative dwell and oversized integer coefficients leaked `OverflowError`.
Normalize counts before arithmetic and reject unrepresentable coefficients with
`ValueError`. Regression tests cover both fixes; property tests check monotonicity
and endpoint bounds. All four targeted mutations (NumPy overflow, linear growth,
disabled penalty and scaling base dwell) were caught. Full suite: 1228 passed;
144 dwell cases give 100% statement/branch coverage. Ruff lint/format passed for
tracked Python files with configured exclusions; whitespace checks passed.
PR review: document the Metro-only model and fixed REM dwell; accept and
normalize `numbers.Real` coefficients, including NumPy scalars. Infer arrival
load by passenger conservation and use the peak of arrival/final load for
crowding, rejecting impossible passenger movements. Make the exponent
configurable (default four, strictly greater than one) for sensitivity analysis.
Regressions cover a packed train unloading, mixed passenger flows, NumPy
coefficients and alternate exponents. Five further targeted mutations (final
load only, wrong arrival conservation, hardcoded exponent, unnormalized
coefficients and allowing a linear exponent) were caught. A corresponding
Mathematical Foundations section 4 wiki update is prepared separately.
Dynamic departure scheduling remains separate.
